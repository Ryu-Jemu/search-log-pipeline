# 1단계 · 원천 데이터와 재생기

## 원천: MS MARCO ORCAS
- 클릭된 (쿼리, 문서) 쌍. 필드는 `qid`, `query`, `did`, `url` 네 개뿐이다.
- 시각·세션·사용자·노출 수가 **없다**. 그래서 이 프로젝트의 이벤트 스트림은 실제 로그가 아니라 **재생 시뮬레이션**이다.
- 이용 조건: 비상업적 연구 목적. 원본은 저장소에 넣지 않고 `scripts/download_orcas.sh`로 받는다.

## 재생기 가정 (`src/slp/generator.py`)
ORCAS에 없는 값은 모두 아래 가정으로 만든다. 지표 수치 해석 시 이 가정을 함께 밝힌다.

| 값 | 가정 |
|---|---|
| 쿼리 인기도 | 쿼리별 클릭 문서 수에 비례해 추출 |
| 시각 | 가상 시계(2026-01-05 00:00 UTC 시작). 세션 시작 빈도는 04시 최저·16시 최고(배수 0.2~1.0) |
| 사용자 | 기본 10만 명, 활동량은 순위^-0.8 가중 |
| 세션 | 검색 수 기하분포(평균 2.2), 검색 간격 2초+지수(평균 20초) |
| 클릭 | 검색 뒤 60% 확률, 그 쿼리의 문서 중 균등 선택, 지연 지수(평균 8초) |
| 늦은 도착 | 0.2% 이벤트를 60~600초 늦게 내보냄 |
| 형식 오류 | 0.05% 이벤트를 잘린 JSON·필수 필드 누락·시각 형식 오류로 변형 |

### 어뷰징 주입 (정답 라벨은 이벤트에 넣지 않고 `labels.json`으로만 출력)

| 유형 | 내용 | 하루 기본 횟수 |
|---|---|---|
| query_flood | 봇 1명이 중간 인기 쿼리를 1~4초 간격으로 20~40분 반복, 클릭 없음 | 3 |
| click_spam | 봇 1명이 같은 쿼리 검색 후 같은 문서를 2~6초 간격으로 반복 클릭 | 3 |
| distributed_flood | 30~60개 계정이 같은 쿼리를 각자 3~8회만 검색 | 2 |

봇 계정 ID는 정상 사용자와 같은 형식(`u0000000`)이라 ID 모양으로는 구별할 수 없다.

## 재생기 실측 (작업 공간: 2 vCPU, 7.8 GiB RAM. 속도·메모리는 콘솔 측정값이며 원자료 파일은 없음)

기본 설정, 가상 1일, seed 42:
- 이벤트 710,340건: 검색 444,363, 클릭 265,977
- 어뷰징 5,414건(0.76%), 늦은 도착 1,399건, 형식 오류 388건
- 생성 속도 약 27,000건/초, 최대 메모리 약 1.28 GB(쿼리 1,040만 개 적재)
- 시간대별 이벤트 수(JSON으로 읽히는 줄 기준): 최저 03시 9,686건, 최고 16시 49,645건
